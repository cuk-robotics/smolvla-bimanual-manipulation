# 음료별 녹화 실행안 — 2026-10-19

**통합 완료:** 아래 계획으로 수집된 가루3종의 정상30개+복구5개를 각각35개로 통합하여 새 공개 저장소3개에 업로드하고 원격 해시를 검증했다. [결과와 원본 회차 대응](powder-merged35-20261019.md)을 참고한다. 원본 보존·학습 미실행이며 아래 수집 명령은 새 수집용이다.

현재 VS Code **CMD** 터미널에서 위부터 한 명령씩 실행하는 안내다. 과거 `SUBTASK_RECORD_GUIDE.md` 대신 새 가루 3종·공통 물 수집에는 이 문서를 사용한다. 한 명령의 녹화·업로드·종료가 완료되고 CMD 입력 프롬프트가 돌아오면 다음 명령을 실행한다.

## 수집량과 작업 입력

| 순서 | 대상 | 에피소드 수 | 해당 실행의 episode_index | 재배치 |
| --- | --- | ---: | --- | ---: |
| 1 | 빨강 뚜껑·커피 가루 | 30 | 0~29 | 20초 |
| 2 | 파랑 뚜껑·아이스티 가루 | 30 | 0~29 | 20초 |
| 3 | 초록 뚜껑·녹차라떼 가루 | 30 | 0~29 | 20초 |
| 4 | 커피 가루가 든 컵에 물 | 18 | 0~17 | 25초 |
| 5 | 아이스티 가루가 든 컵에 물 | 18 | 0~17 | 25초 |
| 6 | 녹차라떼 가루가 든 컵에 물 | 18 | 0~17 | 25초 |
| 기본 수집 합계 | 가루 정상 90 + 물 54 | 144 | 실행마다 0부터 시작 | |
| 7 | 커피 가루 복구 후 성공 | 약 5 | 0~4 | 20초 |
| 8 | 아이스티 가루 복구 후 성공 | 약 5 | 0~4 | 20초 |
| 9 | 녹차라떼 가루 복구 후 성공 | 약 5 | 0~4 | 20초 |
| 추가 포함 합계 | 가루 정상 90 + 가루 복구 15 + 물 54 | 159 | 각 복구 실행도 0부터 시작 | |

색·재료 대응은 사용자 지시로 확인했다. 가루는 **색별 정상 성공 30개를 먼저 확보하고, 복구 후 성공 약 5개를 별도 세션으로 추가 녹화**한다. 정상 30개 원본과 복구 5개 원본을 보존하고, 검증 후 종류별 35개 학습용 통합본을 만든다. 가루 기본 90개·물 54개는 144개이며, 복구 15개를 모두 확보하면 가루 105개·물 54개로 총 159개다. 통합본은 원본의 재구성이므로 새 시연으로 중복 집계하지 않는다. 별도 평가 시도는 수집량에 포함하지 않는다. 30+5는 프로젝트의 초기 비교안이며 충분성·최적 비율은 검증되지 않았다. 물은 세 음료의 목표 물 양·비커·동작이 같다는 조건이다.

`--task`가 학습용 작업 텍스트다. 가루는 **붓기·재료명·뚜껑 색·컵**, 물은 **물 붓기·컵**만 담은 짧은 영어 문장으로 통일한다. 파지·시작점 반납·팔 대기는 문장에서 생략하지만 아래 수집 절차대로 모든 시연에 포함한다. 새 데이터로 학습한 정책의 추론에도 해당 작업과 동일한 문장을 사용한다.

**색·재료를 함께 명시하는 이유:** [SmolVLA 논문 §3.2·부록 A.1](https://arxiv.org/html/2506.01844v1#A1.SS1)은 짧고 명확한 동작 중심 설명을 사용한다. 부록의 “최대 30자”는 사전학습 데이터 설명 생성 프롬프트의 지침이며 모델 입력의 필수 제한이나 최적 길이 실험 결과가 아니다. [같은 논문 §4.1](https://arxiv.org/html/2506.01844v1#S4.SS1)의 쌓기·분류 작업은 빨강·파랑 큐브를 지시문에서 구분한다. 이를 참고해 세 통이 함께 보이는 이번 환경에서는 재료명에 시각적 식별 단서인 뚜껑 색을 덧붙인다. 이는 프로젝트 설계 판단이며 색+재료 문장이 재료만 쓴 문장보다 우수하다는 실험 근거는 없다. 빨강=커피·파랑=아이스티·초록=녹차라떼 대응을 수집·추론에서 유지하며, 색·내용물·위치를 바꿨을 때의 일반화는 별도 평가 대상이다. 문장에 색을 넣는 것만으로 모델의 색 활용이나 내용물 인식을 보장하지 않는다.

사진상 팔 방향과 설정 좌우 대응이 미확인이라 문장에서 left/right를 생략한다. 텍스트가 사용할 팔을 강제 선택하는 기능은 없으며 실제 시연에서는 사진상 오른팔로 가루, 사진상 왼팔로 물, 비작업 팔은 정해진 대기 자세를 유지한다. 하드웨어 매핑·관절 순서는 변경하지 않는다.

새 수집의 기본 저장소 이름은 과거 데이터와 구분하기 위한 `v2`다. 이는 프로젝트 명명이며 LeRobot 파일 형식 버전이 아니다. 물의 세 실행은 컵 상태를 구분하기 위해 저장소 이름만 다르고 작업 텍스트는 같다. 공통 물 정책 학습 시 세 데이터셋을 함께 사용하도록 별도 준비해야 하며 자동 병합·학습은 수행하지 않는다.

## 격자와 회차 배분

각 통의 기준 중심 및 비커의 기준 중심마다 **가로·세로 1 cm 간격인 3×3 점 9개**를 표시한다. 아래 위쪽은 작업대 뒤쪽, 아래쪽은 작업자 쪽이다. 로봇 설정의 left/right 이름과 구분한다. 통/비커 바닥 중심을 해당 점에 맞추며 방향은 유지한다.

```text
작업대 뒤쪽
P1   P2   P3
P4   P5   P6
P7   P8   P9
작업자 쪽
```

P5가 기준 중앙이다. 각 축 ±1 cm, 중심에서 모서리까지 약 1.4 cm다. 해당 범위에서 다른 통을 옮겨야 할 정도로 간섭하면 기본 간격이나 이동 범위를 먼저 조정한다.

| 위치 | 가루 정상: 각 종류의 episode_index | 개수 | 물: 각 재료 조건의 episode_index | 개수 |
| --- | --- | ---: | --- | ---: |
| P5 중앙 | 0~5 | 6 | 0~1 | 2 |
| P1 | 6~8 | 3 | 2~3 | 2 |
| P2 | 9~11 | 3 | 4~5 | 2 |
| P3 | 12~14 | 3 | 6~7 | 2 |
| P4 | 15~17 | 3 | 8~9 | 2 |
| P6 | 18~20 | 3 | 10~11 | 2 |
| P7 | 21~23 | 3 | 12~13 | 2 |
| P8 | 24~26 | 3 | 14~15 | 2 |
| P9 | 27~29 | 3 | 16~17 | 2 |
| 합계 | | 30 | | 18 |

이는 **작업자가 수동으로 지키는 순서**다. 프로그램이 점 위치를 안내·이동하거나 성공을 판정하지 않는다. 로그의 `Recording episode 0`이 첫 회차다. 실패 재녹화는 같은 회차·같은 점에서 수행한다. 가루 시연은 통을 그 회차 시작점으로 반납하며 다음 위치 변경은 재배치 때 한다.

## 물 단계 공통 초기화

비커 중심용 1 cm 간격 9점 격자를 사용한다. 세 가루 조건마다 P5→P1→P2→P3→P4→P6→P7→P8→P9에서 각 2회, 총 18개다. 비커는 그 회차 시작점에 반납한다. 컵·머들러 받침은 고정한다. 가루통은 기본적으로 반납 기준 위치에 두고 실제 가루 단계의 작은 반납 편차를 일부 재현하되 별도로 기록한다. 가루통 위치와 비커 위치를 전수 조합하지 않는다.

매회 이전 음료를 비우고 필요시 세척·건조한 컵에 해당 가루만 정한 양을 넣는다. 가루 단계 종료 후의 통·팔 자세를 사람이 재현해도 된다. 비커 초기 물 양·방향, 목표 물 양, 비작업 팔 대기를 맞춘다. 비커 파지→물 붓기→비커 반납→팔 대기만 녹화하며 가루 투입·젓기는 포함하지 않는다. 25초 안에 준비하기 어렵다면 다음 실행의 `--reset-seconds`를 늘린다. 재배치 동안에도 원격조작이 계속되며 자동 일시정지가 아니다.


### 채택 기준과 회차 기록

- 기존 대기 자세·빈 컵에서 시작해 **가벼운 파지 실패 → 그리퍼 다시 열기·필요한 후퇴 → 위치/각도 재정렬 → 재파지 → 붓기 → 통을 해당 시작점에 반납 → 팔 대기**까지 전체 작업을 기록한다. 복구 구간만 잘라 녹화하는 계획이 아니다.
- 실패 상태와 수정 과정이 카메라·관절 상태에서 구분되고, 짧고 명확한 수정 후 성공한 시연을 채택한다. 여러 번 헛잡기·장시간 정지·통 전도·사람이 손으로 통을 옮겨 해결한 시연·작업 미완료는 초기 통합본에서 제외한다. 5개를 채우려고 일부러 통을 충돌·전도시키거나 정상 시연을 복구 시연으로 분류하지 않는다.
- 정상 수집의 9점 범위에서 실제 실패가 관찰된 위치를 우선 사용하고 시작점 P1~P9를 기록한다. 복구 5개에는 정상 30개의 격자 회차표를 다시 적용하지 않는다. 다른 두 통은 기준점에 고정하며 시작 방향·가루 양·출구 상태는 정상 세션과 맞춘다.
- 채택 가능한 복구가 5개보다 적으면 확보한 수만 보존한다. 명령은 품질을 자동 판정하지 않으므로 녹화 후 재검토한다. 세션을 나누면 다음 실행의 `--episodes`를 남은 수로 조정하고, 새 세션의 번호가 다시 0부터 시작한다는 점을 기록한다.
- 다음 항목을 회차별로 남긴다. `session_path`는 실제 로컬 경로 또는 시각 접미사가 붙은 실제 Hub 저장소다. `normal`/`recovery`는 별도 관리 기록이며 현재 실행기가 자동 저장하는 feature가 아니다.

| session_path | 원본 episode_index | 종류 | normal/recovery | 시작점 | 실패·수정 내용 | 전체 완료 여부 | 채택 여부·이유 |
| --- | ---: | --- | --- | --- | --- | --- | --- |
| 실제 세션 경로 입력 | 0 | 커피 | recovery | 실제 P번호 | 관측한 실패와 재파지 과정 | 기록 | 검토 후 기록 |

### 원본 보존·학습용 통합·비교

1. 종류별 정상 30개와 복구 약 5개를 별도 원본으로 보존한다. 복구 여부만으로 작업 문장을 바꾸지 않는다. 목표 재료가 다른 세 종류 사이의 작업 문장 차이는 유지한다.
2. 병합 전 실제 메타데이터와 세션 기록에서 FPS·robot_type·카메라 키/해상도·state/action의 순서/단위/차원·보정 및 제어 조건을 대조한다. 키가 같아도 보정이나 action 의미가 달라진 세션은 바로 합치지 않는다. 영상과 행동의 정렬, 파일 읽기·영상 디코딩, 전체 완료 여부도 확인한다.
3. 설치된 공식 LeRobot 병합 기능으로 **새 학습용 통합본**을 만든다. 폴더·영상 파일을 수동으로 이어 붙이지 않는다. 실제 경로·버전·채택 목록을 확정한 뒤 병합 명령을 구성한다. 녹화 명령만으로 병합은 실행되지 않는다. [데이터 계약](data-contract.md)과 [기존 병합 이력](huggingface.md)을 참고한다.
4. 정상 30개를 먼저, 복구 5개를 뒤에 넣는 경우 통합 번호 0~29/30~34로 관리할 수 있으나 **실제 결과를 확인해 원본 세션·원본 번호 ↔ 통합 번호 대응표를 보관**한다. 원본 수/프레임 수 합계, 행동 값·작업 문장 보존, 영상 연결, 에피소드 경계와 재인덱싱 후 통계를 검증한다. 제외가 있으면 실제 채택 수로 다시 계산한다.
5. 같은 초기 모델·학습 설정·평가 조건으로 정상 30개만 사용한 모델과 통합 35개를 사용한 모델을 비교한다. 가능한 경우 여러 학습 시드로 확인한다. 첫 파지 성공률, 파지 실패가 발생한 시도 중 복구 성공률, 전체 성공률, 완료 시간·흘림·반납 실패를 구분해 기록한다. 실패 시도 수가 적으면 복구 성공률을 확정적으로 해석하지 않는다.
6. 복구 세션을 나중에 녹화하거나 통합본 뒤에 배치하는 것은 단계별 학습을 뜻하지 않는다. 5/35≈14.3%는 에피소드 수 비율이며, 프레임 기반 표본 추출에서는 길이에 따라 학습 비중이 달라질 수 있다. 세 종류를 하나의 정책으로 학습할지 또는 종류별로 학습할지는 별도 결정이다.

근거의 범위: [Sirius 연구](https://ut-austin-rpl.github.io/sirius/)는 정책 실행 중 사람의 교정과 표본 가중치 조정의 효과를 보고한다. 일반 SmolVLA 학습에서 정상 30개+복구 5개의 최적성이나 단순 병합의 성능 향상을 입증하지는 않는다. 별도 원본 보관은 추적·선별·비교를 위한 운영 결정이다.

## 정상 30개·통합 35개 학습·평가와 후속 수집

1. 가루는 색별 중앙 6개+주변 8점×3개=30개, 총 90개의 정상 성공 시연을 기본 비교 대상으로 보존한다. 별도 복구 약 5개/종을 검증·통합해 위 절차로 30개와 35개 학습을 비교한다. 학습 방식·정책 통합·데이터 병합은 별도로 준비하며 이 문서의 녹화 명령이 학습을 실행하지 않는다.
2. 학습과 별개인 실물 평가에서 색별 대상 선택·파지·붓기·시작점 반납·팔 대기를 점검한다. 격자 사이 위치를 포함하고 색별 시도 수·성공 수·실패 단계·위치를 기록한다. 예를 들어 색별 10회로 먼저 진단할 수 있으나 이는 정밀한 성공률 추정이나 충분성 인증이 아니다.
3. 특정 위치·파지·붓기 조건에 실패가 집중되면 간섭·시야·시연 품질·학습 설정을 먼저 확인하고, 필요한 조건의 성공 시연을 추가 수집해 재학습한다. 색별 50개는 후속 검토 수량이며 반드시 채울 목표로 고정하지 않는다.
4. 추가 수집도 같은 작업 문장·영상 스키마·색과 재료 대응을 유지한다. 추가 실행은 별도 세션 데이터셋이며 자동 resume·병합이 없으므로 실제 저장소와 회차·조건을 기록한다. 실패 분석에 사용한 평가 조건을 학습에 반영했다면 별도의 최종 평가를 확보한다.

[SmolVLA 공식 안내](https://huggingface.co/docs/lerobot/v0.6.0/en/smolvla#collect-a-dataset)는 약 50개를 시작점으로 권하며 큐브 집기·놓기에서 25개로 부족했던 사례를 설명한다. 이는 현재 가루 붓기의 필수 수량을 입증하지 않는다. 이번 30개 시작안은 초기 수집 부담을 줄이고 학습·평가 결과에 따라 보강하는 프로젝트 결정이다.

## 녹화 키와 업로드

1. 실행 전 첫 회차를 준비한다. `Recording episode N` 이후 작업한다. `--episode-seconds 180`은 최대 시간이며 매회 180초를 채우지 않는다. 작업 완료·물체 반납·대기 자세 후 **→**로 시연을 마친다.
2. `Reset the environment`에서만 사람이 컵·가루·물·시작 위치를 초기화한다. 가루 20초, 물 25초 후 다음 회차가 자동 시작되므로 손을 치우고 리더를 안정적으로 유지한다. 준비가 일찍 끝났을 때만 →로 재배치를 조기 종료할 수 있다. 첫 회차 전과 마지막 완료 회차 후에는 이 재배치 시간이 자동 제공되지 않는다.
3. 정상 수집에서 실패하거나 복구 세션의 채택 기준을 충족하지 못하면 **←**로 그 회차를 버리고 같은 점에서 재녹화한다. **복구 세션에서 가벼운 파지 실패를 짧게 수정해 전체 작업을 완료했다면 버리지 않고 →로 마친다.** 정상 수집은 저장 성공 회차 수에 맞춰 격자 순서를 관리한다. 180초 만료로 자동 종료된 시연도 성공 판정은 아니므로 작업이 미완료라면 재배치 중 ←로 다시 기록한다.
4. 목표 수를 마치면 자동 정리·연결 해제·업로드가 진행된다. 중간에 나누어 종료하려면 성공 시연을 →로 마친 뒤 재배치 중 **Esc**를 누른다. 시연 중 Esc는 미완료 시연도 저장할 수 있다. Ctrl+C나 강제 종료를 정상 저장·업로드 방법으로 사용하지 않는다.
5. 마지막 회차는 재배치 없이 저장으로 넘어가므로, 시연을 끝내기 전에 완료 여부를 확인한다. 재배치 중에도 모터가 연결되어 있고 직전 시연의 최종 저장은 그 뒤다. 카메라 오류·강제 종료 시 진행 시연 보존을 보장하지 않는다.

모든 명령은 `--push-to-hub`로 **해당 명령의 녹화 종료 후 공개 업로드**를 요청한다. 각 에피소드가 끝날 때마다 업로드하는 방식은 아니다. 실제 Hub 이름에는 한국 시간 `YYYYMMDD_HHMMSS_마이크로초`가 자동으로 붙는다. 시작 시 표시되는 `Hub destination`은 예정 주소이며 업로드 성공 증거가 아니다. 업로드 성공·프로그램 종료·CMD 프롬프트 복귀까지 기다린 뒤 다음 태스크를 준비한다.

로컬 결과는 `data/lerobot/<명령의 기본 repo_id>/<실행시각>/`에 남는다. 네트워크·권한 오류가 나면 폴더를 보존한다. 자동 재업로드·자동 resume·여러 실행 자동 병합은 없다. 기존 로컬 폴더와 정확한 Hub ID를 지정하는 명시적 `record --resume`은 지원하며, 전체 명령은 [이어쓰기 안내](archive/resume-greentea-20261019.md)에 있다. 이때 `--episodes`는 추가할 수이며 기존 번호를 잇는다. `--resume` 없이 실행하면 별도 세션의 episode_index=0부터다. 이전 격자 회차 기록을 이어 관리한다.

## 범위·근거·검증

- 젓기는 최신 계획의 받침 파지·동일 받침 반납이 기준이나 설치·성공·교반 횟수·시간·수집량은 미정이다. 이번 기본 6개·복구 3개 실행에는 포함하지 않는다. 과거 유리컵 반납 명령을 현재 조건에 그대로 쓰지 않는다.
- [최신 작업·수집 기준](workspace.md), [Hub 종료·저장 설명](huggingface.md), 설치된 `lerobot_record.py`와 `utils/keyboard_input.py`, 저장소 `cli.py`·`recording.py`를 대조했다.
- [LeRobot 공식 녹화 안내](https://huggingface.co/docs/lerobot/main/il_robots): 기록 키·재배치 구간의 일반 사용법. 실제 저장·종료 순서는 이 PC에 설치된 코드를 우선했다.
- [SmolVLA 공식 안내](https://huggingface.co/docs/lerobot/v0.4.3/en/smolvla): 위치 변화별 충분한 시연과 5개 위치·50개 수집 예시. 현재의 가루 9점·30개/종 및 물 총54개의 충분성을 입증하지 않는다.
- 최초 실행안 검증(작업 문장 축약 전): 6개 명령 모두 `--validate-only` 종료코드0·공식 record 설정·카메라3개 배치 검사 통과. 가루50개/20초·물18개/25초·최대180초·30 FPS·공개 업로드 옵션·물3조건 동일 문장도 확인했다. `scripts/check_config.py`, 기존 단위검사38개, 변경 문서의 로컬 링크·공백 검사 통과. 당시 로그는 Git 제외 `outputs/recording_plan_validation_20261019/`에 보관한다. 실물 녹화·모터/카메라 연결·업로드·학습 성능은 검증하지 않았다.
