# 음료 제조 long-horizon 작업 연구 검토

2026-10-19 현재 기준은 [작업·수집 최종 정리](../workspace.md)입니다. 커피·녹차라떼·아이스티 키워드 선택 → 사진상 오른팔 가루 → 사진상 왼팔 물·젓기 순서입니다. 머들러는 젓가락 받침 위 수평 배치·같은 받침 반납을 우선 시험합니다. 사진상 좌우와 설정 좌우는 대응 확인 전이며 자동 연쇄 실행이 구현된 것은 아닙니다. 아래 설명·정책 비교·각 50개 계획은 당시 검토로 보존합니다.

검토일: 2026-10-03. 사용자 설명, 로컬 실행 코드·설정, 아래 논문·공식 문서·사용자 사례를 대조했다. 실제 데이터, 학습 로그, GPU 메모리, 로봇 성공률은 측정하지 않았다. 이 문서는 제안이며 실행 기능 구현이나 최종 수집 방침의 확정을 뜻하지 않는다.

2026-10-06 사용자 결정: 단계별 50개씩 수집하며 단일 모델·단계별 모델의 선택은 이후에 결정합니다. [현재 수집 명령](subtask-recording-20261006.md)을 따릅니다. 아래 정책 구조·완료 판정은 검토 제안입니다.

## 배경과 현재 차이

2026-10-05 당시 작업은 중앙 용기에 왼팔 가루 투입·통 복귀, 오른팔 물 투입·비커 복귀, 왼팔 머들러 젓기·반납이다. 2026-10-03 검토 때 기록 설정의 기본 `single_task`는 이전 설명이었으나 2026-10-05 작업 순서가 갱신됐다. 2026-10-06 사용자 요청으로 물 정량 표기를 제거했으며 물 단계는 비커를 약 절반 채우고 커피가루가 들어간 컵에서 시작하도록 권장한다. 기존 학습 데이터의 실제 task 라벨은 별도 확인 필요다.

2026-10-05 후속 확인: 기존 데이터 메타데이터와 2,000스텝 SmolVLA 체크포인트·저장된 카메라 미리보기 화면을 직접 확인했다. 최초 검토 당시의 미확인 상태와 구분하며, 실물 성공률은 여전히 미검증이다. [Matcha Bot 비교 및 카메라 검토](matcha-bot-comparison.md)를 참고한다.

전체 10개 시연 학습 후 rollout이 원활하지 않았다는 사용자 설명이 있다. 시연 다양성 부족, 단계 혼동, 상태 누적 오차, 정규화·카메라 매핑·제어 주기 불일치 등을 가설로 검토할 수 있으나 현재 원인을 확정할 근거는 없다.

## 우선 권고 구조

1. 가루 투입·통 복귀 / 물 투입·비커 복귀 / 젓기·반납을 각각 하나의 skill로 정의한다. 특정 skill의 접근·파지 등이 계속 실패할 때 추가 분할을 검토한다.
2. 고정된 순서를 상태 머신으로 관리하고, SmolVLA에 현재 skill의 지시를 전달한다. 초기에는 사람이 전환을 승인해 조작 정책 자체를 평가한다.
3. 이후 측정 가능한 완료 조건을 적용한다. 같은 데이터와 평가 조건으로 skill별 ACT 정책을 비교한다. 기본 ACT는 언어 조건 정책이 아니므로 상태 머신이 정책을 선택한다.
4. 완료 판정이 병목이면 짧은 영상 이력·관절 상태·skill ID를 입력하는 별도 완료 분류기를 검토한다. SmolVLA의 공유 특징에 완료 헤드를 붙이는 것은 추가 개발·검증이 필요한 후속 연구다.

상위 제어기는 순서 선택, 완료 판정, 재시도·중단을 담당한다. 순서가 고정된 과제에서 이 기능을 반드시 학습형 VLM으로 구현할 필요는 없다.

## 데이터 수집

- skill별 10개는 파이프라인 확인용 초기 실험으로 취급한다. 30~50개를 다음 수집 목표로 제안하되 성공을 보장하는 임계값으로 해석하지 않는다. 실패가 집중된 조건에 추가 시연을 배분한다.
- 기존 전체 시연을 보존한다. 분할 재사용은 영상만 잘라서는 안 되며, 모든 카메라·state/action·시간·task 라벨·에피소드 경계를 함께 처리한다. 행동 chunk가 다음 skill을 가로지르지 않도록 검증한다. 10개 시연을 3개씩 자른다고 독립적인 전체 시연이 30개로 늘어나는 것은 아니다.
- 물 단계는 가루가 들어간 사발에서, 젓기 단계는 가루와 물이 들어간 사발에서 수집한다. 이전 정책의 실제 종료 위치 편차를 다음 skill의 시작 상태 데이터에 포함한다.
- 처음에는 사발·도구 거치 위치와 카메라를 고정한다. 이후 시험할 범위 안에서 시작 위치·파지·조명 등의 변화를 계획적으로 추가한다. 도구 부피·투입량 변화와 붓기 궤적 변화도 구분한다.
- 양팔 데이터 구성은 일관되게 유지하고 비활성 팔의 대기 행동도 기록한다. 실제 state/action 차원·순서·단위는 메타데이터와 설치된 장치 코드로 확인한다.
- 수행 중/완료 후의 경계 시점을 기록하고, 완료 후 짧은 안정 구간도 남긴다. 실패·미완료 복귀 사례는 완료 검출의 음성 사례로 분리 관리한다. 실패 행동을 성공 시연의 행동 목표로 무조건 혼합하지 않는다.
- 학습/검증 분리는 원본 에피소드 또는 수집 세션 단위로 한다. 같은 원본의 인접 프레임과 분할 조각이 양쪽에 섞여 검증 결과를 부풀리지 않도록 한다.

## 완료 조건 제안

| 단계 | 작업 결과 | 전환 준비 조건 |
| --- | --- | --- |
| 가루 | 목표 가루량의 투입 확인 | 가루통이 거치 위치에 있고 그리퍼가 해제되며 팔이 대기 영역에 도달 |
| 물 | 단계 시작 대비 목표 물 투입량 확인 | 비커 반납·그리퍼 해제·팔 대기 |
| 젓기 | 머들러 삽입 후 정한 젓기 궤적·횟수 또는 시간 수행 | 머들러 반납·그리퍼 해제·팔 대기 |

사발 아래 무게 센서는 투입량 확인에 유용한 후보이나 현재 하드웨어에 구현되어 있지 않다. 도구 접촉력이 측정에 영향을 줄 수 있으므로 접촉 해제 후 안정된 측정값을 사용한다. 가루는 검출 가능한 분해능과 영점 드리프트를 검증해야 한다. 팔 위치·손목 각도·시간만으로는 실제 내용물 투입을 입증할 수 없다.

도구 거치 지그와 식별 마커는 복귀 판정의 후보다. 그리퍼 관절 상태만으로 물체 파지를 확정하지 않는다. 젓기 횟수·시간은 동작 수행의 대리 기준이며 실제 용해·혼합 품질과 구분한다. 완료 조건 지속 시간과 임계값은 실측으로 정한다. 시간 초과는 성공 전환 대신 실패 처리한다. 단계 전환 시 이전 action queue와 정책 상태의 초기화 및 전환 동작의 연속성을 검증한다.

## 카메라 구성 추가 검토

사용자 설명은 그리퍼 장착 카메라 2대와 데스크 전체를 보는 탑뷰 1대다. 비커는 반투명 플라스틱이며 머들러 보관 용기는 머들러 길이의 약 절반 높이인 유리컵이다. 로컬 설정은 각 카메라 640×480, 30 FPS다. 저장된 `outputs/camera_check` 이미지는 없었으며 실제 프레임, 렌즈 초점, 시점, 프레임 지연은 확인하지 않았다.

손목 영상과 외부 고정 영상의 조합은 타당한 출발점이다. [Look Closer, RA-L 2022](https://arxiv.org/abs/2201.07779)는 두 시점의 상호 보완성을 연구했고, [SeqVLA](https://arxiv.org/html/2509.14138v1)도 양손목과 외부 고정 시점의 3개 영상을 사용한다. 이 근거는 현재 장치에서 모든 목표물이 충분히 관측된다는 검증을 대신하지 않는다.

다음은 이 과제에 대한 설계 제안이다.

| 영상 | 필요한 정보 | 확인할 구간 |
| --- | --- | --- |
| 왼손목 | 그리퍼 양 끝, 가루통 파지면, 머들러 노출부, 유리컵 입구 | 파지 직전, 머들러 인출·반납, 사발 삽입 |
| 오른손목 | 비커 양쪽 경계, 파지면, 비커 입구와 사발의 상대 위치 | 파지 직전, 붓기 시작·최대 기울임 |
| 외부 고정 | 모든 도구의 위치, 사발 테두리, 양팔 작업 공간과 반납 영역 | 팔이나 든 물체가 손목 시야를 가리는 구간 |

- 데스크 전체보다 실제 도구·사발·이동 경로가 화면에서 충분히 크게 보이도록 촬영 범위를 조정한다. 광학적 배치 조정을 우선 검토하고, crop을 사용할 경우 원본과 동일한 학습·추론 전처리 조건을 관리한다. 낮은 해상도 영상의 확대는 사라진 세부 정보를 복원하지 않는다.
- 수직 탑뷰가 모든 높이를 잘 드러내는 것은 아니다. 머들러 축을 따라 보는 시점에서 파지 높이 구분이 어렵거나, 붓는 동안 비커가 사발을 가리면 높은 위치의 사선 고정뷰도 비교한다. 최적 각도는 실제 영상으로 선택하며 일률적인 각도를 정답으로 제시하지 않는다.
- 손목 카메라는 그리퍼 몸체보다 손가락 끝과 그 앞 작업 공간이 보이도록 배치한다. 물체를 잡기 직전의 최소 촬영 거리에서 초점이 맞는지, 물체를 잡거나 손목을 돌린 뒤에도 필요한 영역이 보이는지 확인한다.
- 반투명 비커의 윤곽이 배경과 겹치면 무광 단색 작업 매트, 균일한 조명, 비커 외부의 대비되는 작은 표식을 검토한다. 표식은 투입량을 증명하지 않는다. 투명 물체의 반사·굴절로 RGB-D 깊이 측정도 실패할 수 있다는 [ClearGrasp 연구 설명](https://research.google/blog/learning-to-see-transparent-objects/)을 참고하되, 현재 RGB 기반 정책의 실패를 입증하는 자료로 해석하지 않는다.
- 절반 높이 컵은 머들러의 노출된 부분을 잡을 공간을 제공할 수 있다. 실제 가능 여부는 기울기, 그리퍼 손가락 치수, 컵 테두리와의 간격에 달려 있다. 초기에는 머들러 위치·기울기와 컵 위치를 반복 가능하게 만들고, 노출부 파지 → 테두리를 벗어날 만큼 들어 올리기 → 이동 및 반납 직전 입구 정렬을 확인한다.
- 얇은 머들러는 원본 영상뿐 아니라 정책 전처리 후에도 구분되는지 확인한다. 유리컵 입구와 머들러 하단이 겹치는 반납 구간은 별도 확인한다. 프레임 단위 가시성은 유용한 점검 기준이지만 물체가 일부 가려진 모든 순간을 정책 실패로 단정하지 않는다.
- 휴대폰→DroidCam→OBS 외부 영상은 손목 영상과 획득 경로가 다르므로 시간 지연 차이를 측정한다. 동일한 30 FPS 설정만으로 동기화가 보장되지 않는다. 모든 카메라에 보이는 공통 시각 이벤트를 이용한 비교가 한 가지 점검 방법이다.

추가 카메라 도입은 기존 시점을 조정한 뒤에도 특정 핵심 동작이 관측되지 않을 때 검토한다. 촬영 위치·표식·조명을 바꾸면 기존 시연과 관측 분포가 달라지므로, 새 조건의 학습·평가를 구분한다. 실제 구도를 판정하려면 초기 배치와 파지 직전·붓기·머들러 반납 시점의 3개 영상이 필요하다.

## 모델과 GPU

5070 Ti와 4080 Super는 모두 VRAM 16GB다. ACT와 SmolVLA를 우선 검토하며 Diffusion Policy는 추가 비교 후보다. LeRobot의 BS 8·AdamW 기준 공식 메모리 안내는 Light BC 약 2~6GB, Diffusion 약 8~14GB, SmolVLA 약 10~16GB의 추정 범위를 제시한다. 3개 카메라·배치·학습 범위에 따라 실제 사용량이 달라지므로 본 프로젝트의 실측값으로 해석하지 않는다.

SmolVLA는 사전학습 체크포인트에서 미세조정하는 것을 우선 검토한다. 작은 배치와 encoder 동결부터 실행 가능성을 확인하고, 성능·메모리에 따라 학습 범위를 조정한다. π₀·π₀.₅와 SeqVLA 전체 재현은 16GB 환경의 기본 선택으로 권하지 않는다. PEFT로 가능한 구성은 별도 확인이 필요하며 메모리 적합성과 작업 성공은 구분한다. Blackwell인 5070 Ti는 해당 GPU를 지원하는 PyTorch/CUDA 빌드와 드라이버 조합을 확인한다. 기존 환경의 자동 업그레이드는 제안하지 않는다.

## 평가안

전체 SmolVLA, 단계별 SmolVLA+사람 전환, 단계별 SmolVLA+규칙 전환, 단계별 ACT+동일 규칙을 순서대로 비교한다. 전체 정책과 단계 정책의 비교에는 가능한 한 같은 원본 시연을 사용한다. 추가 수집과 구조 변경의 효과를 혼동하지 않도록 수집량도 기록한다.

skill별 성공률, 실제 이전 skill 출력에서 시작한 연결 성공률, 전체 성공률, 완료 오판·판정 지연, 사람 개입, 투입량 오차를 따로 기록한다. 평가 횟수는 계획값으로 정하고 성공/전체 횟수를 함께 보고한다. 학습 loss만으로 실물 성공을 판단하지 않는다.

## 근거와 적용 한계

- [SmolVLA 논문](https://arxiv.org/html/2506.01844v1): SO-100/SO-101 실물 평가와 multi-task 미세조정의 근거다. 이 음료 제조 과제의 성능 근거는 아니다.
- [LeRobot SmolVLA 안내](https://huggingface.co/docs/lerobot/v0.6.1/smolvla): 약 50개부터 수집하라는 공식 시작 권고와 사전학습 모델 미세조정 안내다. 단순 pick-place에서 25개가 부족했던 사례를 장기 음료 과제의 충분한 데이터 수로 일반화하지 않는다.
- [ACT 연구](https://tonyzhaozh.github.io/aloha/): 양팔 정밀 조작의 행동 chunk 정책 사례다. ALOHA 결과를 SO-101 성공률로 옮겨 쓰지 않는다.
- [SeqVLA](https://arxiv.org/html/2509.14138v1): π₀에 완료 검출 헤드를 추가하고 단계별 프레임을 수동 라벨링한다. 실험은 ALOHA이며 SmolVLA/SO-101 적용은 별도 검증 대상이다. 논문 라벨은 1=수행 중, 0=완료 후다.
- [Hi Robot, ICML 2025](https://arxiv.org/abs/2502.19417): 복잡한 지시·피드백을 해석하는 상위 모델과 저수준 행동 정책을 분리한 사례다. 고정 순서 과제에서 상위 모델 학습이 필수라는 근거는 아니다.
- [Subgoal Transitions, CoRL 2025](https://proceedings.mlr.press/v305/jain25b.html): 부적절한 휴리스틱 전환의 취약성과 전환 학습을 검토한다. 실측 가능한 규칙으로 시작하되 전환 오류를 별도 평가해야 한다는 판단에 참고했다.
- [SO-101 비교 연구, 2026 preprint](https://arxiv.org/html/2606.08881v1): 모델 순위가 과제에 의존하고 실패·복구 평가가 필요함을 보여 준다. 단일 팔·제한된 과제와 평가 횟수이며 본 프로젝트 양팔 음료 작업을 검증하지 않는다.
- [Diffusion Policy](https://diffusion-policy.cs.columbia.edu/): 액체 붓기 및 주기적 조작 사례를 제공하지만 본 프로젝트 적용 결과는 없다.
- [LeRobot GPU 안내](https://huggingface.co/docs/lerobot/v0.6.1/hardware_guide), [NVIDIA 5070 제품 사양](https://www.nvidia.com/en-au/geforce/graphics-cards/50-series/rtx-5070-family/), [NVIDIA 4080 제품 사양](https://www.nvidia.com/en-us/geforce/graphics-cards/40-series/rtx-4080-family/), [PyTorch Blackwell 지원](https://pytorch.org/blog/pytorch-2-7/): GPU 용량과 실행 환경 확인의 근거다.
- [Reddit SO-101 미세조정 실패 보고](https://www.reddit.com/r/robotics/comments/1qxm907/does_anyone_have_experience_with_finetuning/), [Reddit 16GB GPU SmolVLA 실행 사례](https://www.reddit.com/r/robotics/comments/1vp27ra/built_a_small_autonomous_household_robot_that_can/): 서로 다른 사용자 경험으로, 통제 실험이나 본 과제 성공률의 근거로 취급하지 않는다.
