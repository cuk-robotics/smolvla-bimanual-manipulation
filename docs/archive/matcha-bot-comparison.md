# Matcha Bot 비교 및 카메라 시점 검토

2026-10-07 갱신: 현재 가루 50개·물 50개 및 전달받은 10,000스텝 체크포인트에 대한 [데이터·학습 개선안](powder-data-improvement.md)을 추가했다. 사용자는 실패 시연 재녹화·카메라 고정·매회 용기 비움을 확인했다. 가루 수치 검사와 영상 표본, 검증 시연의 행동 예측을 점검했으며 전체 재수집보다 학습량·파지 구간 추론 비교를 우선한다. 아래의 10개 데이터·2,000스텝 수치는 10월 5일에 검토했던 과거 자료다.

검토일: 2026-10-05. 공개 기사·연결된 GitHub 코드와 캡처·데모 장면, 로컬 데이터 메타데이터·체크포인트·저장된 미리보기 화면을 읽기 전용으로 확인했다. 실제 로봇 실행, 추가 학습, 성공률 측정은 수행하지 않았다. 아래 배치·평가안은 제안이며 확정된 구현 계획이 아니다.

## 핵심 판단

- 현재 과제에서는 손목 2대와 외부 고정 1대를 유지하고, 수직 탑뷰와 높은 사선뷰를 비교할 가치가 있다. 첫 사선 후보는 광축과 수평 작업대 사이 약 60도다. 이는 검증된 최적값이나 Matcha Bot의 실측 각도가 아니다.
- 우선 참고할 부분은 단계별 데이터 구성과 시작·완료 상태의 구별이다. GR00T 교체가 현재 실패를 해결한다는 비교 근거는 없다.
- 우리 과제는 비커·가루통 복귀와 머들러 반납까지 요구한다. 제작팀이 설명한 물 용기 낙하·젓는 중 기록 종료를 그대로 적용하면 목표가 달라진다. [제작팀 기사](https://www.hackster.io/sigrobotics/matcha-bot-sigrobotics-embodied-ai-hackathon-1st-place-f0e520)

## 직접 확인한 비교 근거

| 항목 | Matcha Bot 공개 자료 | 우리 로컬 자료 |
| --- | --- | --- |
| 정책 | GR00T N1.5 | SmolVLA 체크포인트 존재 |
| 데이터 메타데이터 | 공개 코드 루트의 info.json: 82개 에피소드, 54,058프레임, task_index 4개 | 기존 데이터: 10개 에피소드, 41,160프레임, task_index 1개 |
| 입력·출력 | 영상 3개, state/action 각 12차원 | 영상 3개, state/action 각 12차원 |
| 기록 영상 | top_rgb·left·right, 640×480·30 FPS | top·left_wrist·right_wrist, 640×480·30 FPS |
| 관측 이력 설정 | custom_data_config.py의 observation_indices=[0] | 확인한 정책의 n_obs_steps=1 |

외부 근거: [info.json](https://github.com/hmk55555/Isaac-GR00T/blob/main/info.json), [modality.json](https://github.com/hmk55555/Isaac-GR00T/blob/main/modality.json), [학습 데이터 설정](https://github.com/hmk55555/Isaac-GR00T/blob/main/examples/SO-101/custom_data_config.py).

공개 info.json이 대회 최종 학습 데이터와 정확히 일치하는지는 확인되지 않았다. 메타데이터의 task_index 4개를 물리적인 작업 4단계로 해석하지 않는다. 메타데이터상 평균 기록 길이는 외부 약 22초, 우리 약 137초다. 단순 계산값이며 편집·정지 구간 등을 검증한 실제 동작 시간은 아니다. 긴 영상에 많은 프레임이 있다는 사실과 독립적인 시연 다양성은 구분한다.

로컬 근거:

- `data/lerobot/lmsforai/bimanual-test-version/20260930_235637_522048/meta/info.json`
- `outputs/train/smolvla_beverage_20261001_012408_447817/checkpoints/002000/pretrained_model/config.json`
- 같은 체크포인트의 `train_config.json`, `policy_preprocessor.json`, `training_state/training_step.json`

체크포인트 저장 상태는 step=2000, batch_size=2, num_processes=1이다. 약 4,000개 관측 기준 샘플에 해당하며 전체 41,160프레임 대비 약 0.097배다. 실제 epoch는 학습/검증 분리·샘플러의 유효 길이와 로그로 확정해야 한다. 한 샘플은 여러 미래 행동을 포함하므로 이 비율을 전체 행동 프레임의 학습 비율로 해석하지 않는다. n_action_steps=50, chunk_size=50이며 이 설정이 당시 실물 추론에 그대로 적용됐는지는 확인 필요다. 30 Hz로 50개 행동을 재관측 없이 실행한다면 약 1.67초이므로 실제 추론 주기·큐 동작도 점검 대상이다.

기록된 전처리 매핑은 top→camera1, left_wrist→camera2, right_wrist→camera3이다. 이름 변환 자체는 명시되어 있으며 매핑 오류가 발견됐다고 주장하지 않는다. 당시 실제 추론에서도 동일한 물리 카메라·시점·전처리였는지는 확인 필요다.

## 카메라 배치 조사 결과

### 후속 확인: 배속과 XLeRobot 본체 장착 카메라

사용자 후속 질문에 따라 데모 0:04 부근을 재확인했다. 영상 좌하단에 `2X`가 표시되고 확인 시 브라우저 video 요소의 playbackRate는 1이었다. 해당 구간은 플레이어 배속이 아니라 영상 자체의 2배속 편집으로 판단한다. 다른 구간의 동일 배속·편집 생략 여부는 확정하지 않으며 37.861초 영상 길이를 전체 작업 실측 시간으로 사용하지 않는다. 앞의 평균 22초는 영상 길이가 아니라 데이터 메타데이터로 계산한 에피소드 평균이다.

XLeRobot [공식 3D 설계 설명](https://xlerobot.readthedocs.io/en/latest/hardware/getting_started/3d.html#arm-base)은 두 팔의 베이스를 연결해 간격을 일정하게 만드는 구조를 명시한다. 같은 문서의 Neck and head는 중앙 기둥과 헤드 카메라 마운트를 보여 준다. [조립 문서](https://xlerobot.readthedocs.io/en/latest/hardware/getting_started/assemble.html#head-assembly)는 별도 헤드 모터 두 개를 안내한다. 따라서 설계상 전체 시야는 로봇 몸체 중앙 위쪽 헤드에서 전방 작업대를 바라보는 배치이며, 수직 천장 카메라가 필수인 구조가 아니다.

Matcha Bot 데모와 [주최자 사진](https://www.seeed.cc/post/2025-embodied-ai-hackathon-recap)에서 연결된 양팔 베이스와 중앙 기둥을 확인했다. 다만 확인한 장면에서는 기둥 꼭대기 렌즈가 화면 밖이어서, 최종 Matcha Bot에서 헤드 카메라의 실제 사용·기울기·대회에서 남은 두 카메라 조합은 여전히 미확인이다. 공개 작업대 캡처는 이 헤드 시점과 부합하지만 일치 확정의 근거는 아니다.

앞서 사용한 ‘외부 고정뷰’라는 표현은 손목 외 전체 시야 역할을 설명한 것이며 Matcha Bot의 독립 삼각대 장착을 확인한 의미가 아니다. 표준 XLeRobot 구조를 설명할 때는 ‘본체 장착 헤드뷰’가 더 정확하다. 우리 고정 작업대는 두 팔과 별도 카메라 마운트를 견고하게 고정해 상대 위치를 유지하면 유사한 시점을 구성할 수 있다. 양팔 연결 프레임을 새로 만드는 것이 카메라 시점 재현의 필수 조건은 아니다.

[기사에 연결된 저장소의 opencv_1.png](https://github.com/hmk55555/Isaac-GR00T/blob/main/outputs/outputs/captured_images/opencv_1.png)에서 작업대 전체를 위쪽의 사선 방향으로 촬영한 영상을 확인했다. 용기 입구와 옆면, 작업대 앞쪽 양팔 일부가 함께 보인다. 이는 저장된 한 장의 시각적 관찰이며 정확한 광축 각도·설치 높이·초점거리의 측정값은 없다.

같은 폴더에는 그리퍼 근접 화면과 사람·천장을 촬영한 장치 탐색 이미지도 섞여 있다. 기사 수집 예시와 [추론 예시](https://github.com/hmk55555/Isaac-GR00T/blob/main/examples/SO-101/eval_gr00t_so101_new.py)의 장치 번호도 다르다. 따라서 파일 번호만으로 opencv_1=최종 top_rgb라고 확정할 수 없다. 기사는 카메라 고장으로 대회에서 2대를 사용했다고 설명하지만, 남은 카메라의 정확한 조합·재학습 여부는 확인 필요다.

[제작팀 데모](https://www.youtube.com/watch?v=FEa4-pXqAoE)는 외부에서 촬영한 홍보·관찰 영상이다. 영상 촬영 시점을 정책 입력 카메라 시점으로 간주하지 않는다. 결론은 **높은 사선의 작업대 캡처는 확인됐으나 대회 최종 입력의 정확한 각도는 미확인**이다.

우리 `outputs/preview_actual_20261005.png`는 수직에 가까운 전체 시야를 보여 준다. 손목 영상에서는 그리퍼가 상당한 면적을 차지한다. 저장된 대기 자세 한 장으로 파지·붓기·반납 중 가시성을 판정하지 않는다.

## 우리 작업에 대한 배치 제안

| 판단 대상 | 수직 탑뷰 | 높은 사선뷰 |
| --- | --- | --- |
| 사발 입구·평면 위치 | 입구·배치 파악에 유리한 후보 | 원근과 테두리 가림 확인 필요 |
| 머들러 노출부·파지 높이 | 축 방향으로 겹쳐 보일 수 있음 | 옆면과 높이 차의 시각적 단서를 얻을 수 있음 |
| 비커 기울임·붓기 | 비커와 사발이 포개질 수 있음 | 비커 옆면·입구와 사발의 관계를 볼 수 있음 |
| 반납 | 입구 중심 정렬에 유용 | 접근 높이·테두리 접촉 관찰에 유용하나 가림 확인 필요 |

위 내용은 투영 기하와 과제 구조에 따른 설계 판단이다. 사선 RGB 한 장이 정확한 깊이나 투입량을 측정한다는 의미는 아니다.

1. 손목 2대는 유지하고 외부 카메라의 수직 90도와 높은 사선 약 60도(수평 작업대 기준)를 비교한다. 방위는 양팔 링크가 사발·거치대를 덜 가리는 쪽으로 정한다.
2. 책상 전체보다 사발·가루통·비커·머들러 거치컵과 이동 경로를 충분히 크게 포함한다. 사선 때문에 사발 내부가 가려지면 각도를 더 수직에 가깝게 조정한다.
3. 파지 직전, 붓기 최대 기울임, 머들러 인출, 사발 삽입, 거치컵 반납을 확인한다. 필요한 특징이 세 영상 모두에서 사라지는 구간을 우선 개선한다.
4. 원본뿐 아니라 모델 전처리 후 머들러 끝·컵 입구·그리퍼 끝이 구별되는지 본다. 그리퍼 자체의 면적보다 실제 조작 대상이 보이는지가 중요하다.
5. 조명·도구 위치를 고정한 짧은 시연을 각 각도에서 3~5회 비교하는 것을 초기 가시성 점검안으로 제안한다. 이 횟수로 학습 성능 우위를 주장하지 않는다.
6. 가시성 검사를 통과한 후보는 같은 데이터량·학습 조건·평가 시작 상태로 비교한다. 파지·붓기·반납·전체 성공을 따로 기록한다.

카메라 이름 top은 논리 키이며 수직 설치를 강제하지 않는다. 물리 각도만 바꾸더라도 기존 체크포인트와 관측 분포가 달라진다. 기존 데이터는 보존하고 신규 각도·높이·방향·카메라 세션을 기록한다. 키 이름이 같다는 이유만으로 다른 시점 데이터를 검증 없이 합치지 않는다. 휴대폰→DroidCam→OBS 경로의 손목 영상 대비 지연도 확인 대상이다.

## 적용 우선순위

1. 현재 실패를 파지·운반·붓기·복귀·젓기·반납·단계 전환으로 나누어 기록한다. 체크포인트 학습량과 실제 추론의 카메라 매핑·행동 실행 간격을 먼저 확인한다.
2. 단계 지시를 가루 투입·복귀 / 물 투입·복귀 / 젓기·반납으로 분리해 평가한다. 하나의 언어 조건 정책과 단계별 지시로 시작할 수 있으며 세 체크포인트를 반드시 만들 필요는 없다. 초기 단계 전환은 사람이 승인해 조작 실패와 전환 실패를 분리한다.
3. 작업 전후의 용기 거치 위치·팔 대기 위치를 반복 가능하게 만들고 완료 판정을 설계한다. 용기 낙하를 학습시키는 대신 정상 반납을 유지한다. 젓기 종료는 시간·횟수와 도구 반납을 구분한다.
4. 카메라 각도·학습량·정책 구조를 한 번에 변경하지 말고 요인별 효과를 비교한다. GR00T 전환, 서버 분리, 데이터 형식 변환은 현재 파이프라인의 구체적 필요가 확인될 때 검토한다.

## 연구 책임자 관점의 핵심 질문

1. 현재 실패가 조작 대상의 비가시성, 단계 혼동, 학습량·추론 설정 중 어디에 집중되는가?
2. 성공에 투입량·젓기 품질·모든 도구 반납 중 어떤 조건을 포함하며, 각 조건을 어떻게 측정하는가?
3. 카메라 각도의 효과를 데이터량·학습량 변화와 분리해서 검증할 수 있는가?
